# Технический долг

Найдено в ходе работы над прототипом, вынесено за границы текущего скоупа.
Ничего из перечисленного не блокирует запуск и не ломает состояние.

## 1. Прогресс дрилла не переживает уход с экрана

**Severity:** средняя (UX-риск, данные не бьются)

Текущая сессия живёт в переменной `session` в замыкании `app.js` и попадает в
localStorage только на последнем вопросе, в `commitSession()`. Если студент
перезагрузит страницу, нажмёт «Выйти» или кликнет по логотипу / «Колоде ошибок»
в шапке на середине сессии — все ответы теряются молча, без предупреждения.

Места:
- `assets/js/app.js` — объявление `session`
- `assets/js/app.js` — `exitSession()`
- `assets/js/app.js` — обработчики `nav-home` и `nav-deck` не проверяют активную сессию
- `index.html` — кнопка `#drill-exit`

Найдено QA. Само хранилище при этом остаётся корректным — теряется только
незавершённая сессия.

**Что сделать:** двухшаговое инлайн-подтверждение на «Выйти» и на переходы в шапке
во время активной сессии. Переиспользовать паттерн, который уже применён для
удаления карточки из колоды (`Да` / `Нет` прямо в интерфейсе).
Нативный `confirm()` не подходит — выбивается из языка дизайна портала.
Опционально — сохранять частичный прогресс сессии, чтобы её можно было продолжить.

**Почему не сделано сейчас:** выходит за замороженный скоуп прототипа
(см. PLAN.md), требует новой UI-механики и повторного прохода QA.

## 2. Мелочи из code review

**Severity:** низкая

- `renderResult()` (~180 строк) и `renderDeck()` (~107 строк) в `assets/js/app.js`
  монолитны. В том же файле рядом есть удачный контрпример: `renderQuestion()`
  делегирует в `renderBadges` / `renderPassage` / `renderStem` / `renderChoices`.
  Стоит разбить по тому же принципу.
- Сборка бейджей вопроса дублируется в трёх местах (`renderBadges`, список ошибок
  на итоге, карточка колоды) — просится общий хелпер `questionBadges()`.
- Токен `--star:#fbbf24` объявлен в `assets/css/style.css`, но не используется.
  Часть эталонного набора из UI-кита; либо применить, либо убрать.
- Магическое число `86400000` в `daysBetween()` (`assets/js/store.js`) — вынести
  в именованную константу `MS_PER_DAY`.
- Чипсы причин ошибки (`.reason-chip`) имеют `role="radio"` внутри `radiogroup`,
  но, в отличие от вариантов ответа, без roving `tabindex` и навигации стрелками.
  Клавиатурная доступность не сломана, но паттерн реализован непоследовательно.

## 3. Не проверено

- Визуальный рендеринг в реальном браузере: headless Chrome в среде разработки не
  стартует (нет `libnspr4.so` / `libnss3.so` / `libasound.so.2`, sudo недоступен).
  Логика покрыта прогонами в jsdom, пиксели — нет.
- Кросс-браузерность: Safari и Firefox глазами не смотрели. Рискованных свойств
  в CSS нет, `backdrop-filter` деградирует безопасно.
- Бейджи домена и скилла на ширине 360px: добавлена страховка
  (`max-width: 100%` и перенос по словам под 400px), но визуально не подтверждено.
  Самые длинные строки — `Problem-Solving and Data Analysis` и
  `Right triangles and trigonometry` (вопросы `math-03` и `math-04`).
