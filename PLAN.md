# PLAN — тестовое задание Global Generation

## Выбранная идея

**«Разбор» — работа над ошибками для Digital SAT.**

Модуль, который превращает ошибку в разобранный урок: студент решает короткий дрилл,
после каждой ошибки обязан назвать её причину, видит разбор *каждого* варианта ответа
(почему дистрактор — ловушка), а в конце получает карту «где я теряю баллы» и колоду
своих ошибок с интервальным повторением.

### Почему именно это

1. **Закрывает реальную дыру.** На SAT Portal уже есть практика, таймер, ревью и аналитика.
   Чего нет нигде (и в большинстве платформ подготовки) — принудительной рефлексии в момент
   ошибки. Студент смотрит правильный ответ, кивает «а, понятно», и через неделю ошибается
   снова, потому что причина ошибки не зафиксирована. Одна и та же ошибка возвращается на экзамене.
2. **Показывает вкус, а не объём.** Ценность в деталях: разбор на уровне дистракторов,
   обязательный тег причины, срез «тема × причина», а не в количестве экранов.
3. **Честно проходится end-to-end за пару часов** и целиком помещается в статику + localStorage:
   без бэкенда, без ключей, без сборки.

### Зафиксированные решения

| Решение | Обоснование |
|---|---|
| Чистый HTML/CSS/JS, без сборки и без npm | Запуск в один шаг: открыть `index.html`. Нет шага установки — нечему сломаться у проверяющего |
| Скрипты подключаются классическими `<script src>`, без ES-модулей | ES-модули блокируются CORS на `file://`. Работает двойной клик по файлу |
| Хранилище — localStorage, одна версионированная запись | Повторный визит подхватывает прогресс; нет бэкенда |
| Обращение на «ты» | Прямое требование брифа. На самом портале — «вы», но бриф приоритетнее |
| Домены/скиллы и тексты вопросов — на английском | Экзамен англоязычный. Интерфейс и все объяснения — на русском |
| Inter через Google Fonts | Родной способ портала |
| Ветка мержится в main через `--no-ff` | История фичи сохраняется в merge-коммите |

### Явно НЕ делаем (вне скоупа)

Аккаунты, бэкенд, полноразмерный экзамен, adaptive-модуль второй секции, экспорт,
мобильное приложение, реальный SRS-алгоритм уровня Anki (берём упрощённые фиксированные интервалы).

## Путь пользователя (end-to-end)

```
Дашборд → Дрилл (6 вопросов) → [ошибка → выбрать причину → разбор] → Итог «где я теряю баллы»
   ↑                                                                        ↓
   └──────────────── Колода ошибок (повтор по интервалам) ←─────────────────┘
```

1. **Дашборд.** Первый визит — пустое состояние с объяснением механики и одной кнопкой.
   Повторный — статистика: точность, разобрано ошибок, «к повторению сегодня: N».
2. **Дрилл.** 6 вопросов, микс Reading & Writing и Math. Прогресс, таймер на вопрос.
   Ответ → мгновенный разбор: почему верный верный и почему каждый неверный — ловушка.
3. **Тег причины.** Только при ошибке. Обязателен — без выбора нельзя идти дальше.
   5 причин: не знал тему / не понял вопрос / повёлся на ловушку / невнимательность / не хватило времени.
4. **Итог.** Счёт, время против нормы, срез по доменам, срез по причинам,
   2–3 персональные рекомендации, список карточек, ушедших в колоду.
5. **Колода.** Карточки своих ошибок. Верный ответ на повторе → интервал растёт
   (сегодня → 1 → 3 → 7 дней → «усвоено»), ошибка → сброс в начало.

## Экраны

| Экран | Ключевые элементы |
|---|---|
| Дашборд | Hero-градиент, 3 стат-карточки, CTA, блок колоды, пустое состояние |
| Дрилл | Прогресс-бар, таймер, бейдж секции/домена, passage, 4 варианта, разбор, тег причины |
| Итог | Кольцо результата, бары по доменам, бары по причинам, рекомендации, что ушло в колоду |
| Колода | Счётчик «к повторению сегодня», список карточек с интервалами, режим повтора, пустое состояние |

## Структура файлов

```
index.html              единственная точка входа, разметка всех экранов
assets/css/style.css    токены + компоненты
assets/js/data.js       сид-датасет вопросов (отдельный проход, вне UI-задачи)
assets/js/icons.js      инлайновые lucide-подобные SVG
assets/js/store.js      localStorage, SRS-интервалы, агрегация статистики
assets/js/app.js        роутинг экранов, рендер, логика дрилла и колоды
README.md               что это, какую проблему решает, как запустить
SUBMISSION.md           сопроводительный текст
```

## Датасет

12 вопросов: 6 Reading & Writing + 6 Math, покрывают все 8 доменов Digital SAT.
Дрилл берёт 6 за сессию, приоритет — невиденные (2 сессии без повторов).

Схема записи:

```js
{
  id, section: 'rw'|'math', domain, skill, difficulty, targetSec,
  passage: string|null,
  stem: string,
  choices: [{ text, why }] x4,   // text — англ., why — рус. разбор варианта
  correct: number,               // индекс
  explanation: string,           // рус., как прийти к ответу
  trap: string                   // рус., короткое имя ловушки
}
```

## Ограничения стиля

Токены из брифа — без отступлений. Inter 400–800, заголовки 800.
Запрещено: эмодзи, сиреневый/фиолетовый, чужие шрифты, иконочные CDN, Tailwind-дефолт.
Иконки — только инлайновый SVG в стиле lucide (stroke 2, круглые концы, currentColor).

## Риски

| Риск | Митигация |
|---|---|
| Датасет выйдет «дженерик-ИИ» и завалит впечатление | Датасет пишется отдельным проходом под жёстким требованием: каждый дистрактор восстановлен из реальной студенческой ошибки и объяснён |
| localStorage недоступен (приватный режим) | Обёртка try/catch, приложение работает в памяти |
| Открытие через `file://` сломает загрузку скриптов | Никаких ES-модулей и fetch, только `<script src>` |
| «Вылизывание» съест бюджет | Скоуп заморожен списком выше |
